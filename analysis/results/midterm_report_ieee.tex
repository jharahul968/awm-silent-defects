\begin{abstract}
This project tests whether tabular methods recognize SQL-valid injected value defects in unseen Agent World Model (AWM) environments. A reproduced initialization audit and a labeled mutation benchmark support separate analyses of execution failures and value anomalies. Eight methods are compared using disjoint training, validation, and test environments. Completed experiments examine corruption severity, omitted-type transfer, feature groups, repeated splits, and simulated low prevalence. Interpretation and an interactive demonstration use the same saved Random Forest. Results concern controlled mutations; they do not establish detection accuracy for naturally occurring semantic defects.
\end{abstract}

\section{Problem and Progress Since the Proposal}
AWM synthesizes executable database-backed environments for training tool-using agents \cite{wang2026awm}. SQLite detects constraint violations but cannot determine arbitrary business meaning. The mining question is: \emph{Can static statement features detect SQL-valid injected value defects in environments excluded from training?}

The approved proposal compared rules, Isolation Forest, and Random Forest. The expanded benchmark compares eight methods and tests sensitivity to corruption severity, excluded types, feature groups, and environment partitions. The dataset design also changed: unmodified statements are retained alongside separate mutations, instead of replacing a selected subset in place. One working instance is one unmodified or mutated INSERT statement; variants are dependent observations. Proposed positive-value changes, temporal ordering violations, and semantically incorrect references remain future work.

\section{Data, Quality, and Leakage Checks}
The public AgentWorldModel-1K dataset \cite{snowflake2026awm} is fully synthetic and released under CC-BY-4.0. The study uses its schema and sample-data JSONL files. The initialization audit reproduces the upstream SQL execution behavior \cite{snowflakecode}: 129,328 INSERT statements across 1,000 environments include 1,374 execution failures, affecting 217 environments; 1,054 failures are foreign-key violations. One environment has a malformed sample payload. These observations describe runtime defects, not labeled semantic errors.

\RawQualitySummary

The mutation builder preserves successful, supported source statements and checks each candidate under the original schema and preceding database state, with foreign keys enabled. A savepoint rolls back every trial before the next mutation. Label 0 means \emph{unmodified executable source}, and label 1 means \emph{accepted controlled mutation}; neither is a manually verified semantic label. \DatasetSummary

Five mutation families use three severity levels. Money and quantity values become negative at different magnitudes; rating values become 99, 10, or 5.5; ages become 285, 150, or 120; date years become 1823, 1950, or the source year minus 30 (bounded below by 1900). Date shifts and age 120 can be plausible in some domains, so their labels represent the benchmark's assumptions. Unsupported or failed source statements, unchanged mutations, and SQLite-rejected candidates are counted separately in the build metadata. Source/mutated SQL, changed column, original/new values, and hashes are retained. An artifact audit reconciles RF metrics and replays SQL/features for 25 stratified pairs; their semantic judgments remain unreviewed.

The outer \texttt{GroupShuffleSplit} holds out 25\% of environments, and a second grouped split reserves 20\% of the remainder for validation (seed 42). \SplitSummary{} All statements and variants from an environment remain together. Assertions check disjoint environment sets. Parameters and scaling use training data; learned thresholds maximize validation F1; rules use a fixed Boolean cutoff. Test labels do not choose thresholds. Similar schemas may still occur across distinct environments, so grouping does not establish schema novelty.

\section{Features, Methods, and Evaluation}
The 26 pre-execution features comprise 11 literal summaries (signed-log numeric extrema, negative counts, parsed years, string lengths, and NULL counts), eight column/statement features (keyword indicators and column/value counts), and seven schema/position features (foreign keys, uniqueness, width, unknown columns, SQL length, and fill ratio). SQL date expressions are distinguished from literal dates in the quality analysis; a missing parsed year uses a fixed default, not evidence of a true year.

The rule baseline flags row-level numeric/date patterns in the presence of relevant column keywords. A second baseline takes the maximum absolute mean/std Z-score across features. Isolation Forest (200 trees) \cite{liu2008isolation} and novelty-mode LOF ($k=20$) \cite{breunig2000lof} fit unmodified training examples. LOF uses training-only standardization and a deterministic cap of 25,000 fitting examples. Supervised methods are scaled, class-balanced logistic regression; Random Forest (200 trees) \cite{breiman2001random}; histogram gradient boosting (maximum 300 iterations); and XGBoost (300 trees) \cite{chen2016xgboost}, with a training-derived positive-class weight. Full configurations are saved with the results.

The primary metric is average precision (AP), computed by \texttt{average\_precision\_score}; it is not trapezoidal PR-AUC. Random-ranking AP equals positive prevalence. F1 uses validation-selected thresholds (rules: fixed 0.5), and Precision@100/Recall@100 measure ranking. All main results in Table~\ref{tab:main} concern the same held-out environments.

\section{Limitations and Remaining Work}
The benchmark is dominated by repeated date/value mutations, and unmodified rows may already contain natural defects. Mutation-family labels are lexical recipes: matching \texttt{count} also selects the Boolean column \texttt{is\_bank\_account} as an inventory-family candidate. Keyword eligibility does not verify business rules. High AP therefore indicates recognition of these transformations under the stated protocol. Three seeds provide a limited stability check, not a confidence interval. Examining test errors informs further work, so a new final holdout or explicit exploratory designation is needed for conclusions after feature revisions.

During October, representative source/mutated pairs will be reviewed across domains and column-aligned features designed. November experiments will test those features and plausible positive-value or temporal-consistency errors. Configuration will be frozen before evaluation; revisions will be labeled exploratory if an untouched holdout is unavailable. Final bonus evidence must include actual tracking runs, accessible code, continued weekly commits, and a demonstrated end-to-end example; September activity is not established by the current Git history.
